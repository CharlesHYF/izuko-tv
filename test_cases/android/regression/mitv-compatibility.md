## 目标电视用例

以下用例必须在 MiTV4-ANSM0 上执行；host tests 和其他设备不能替代。

1. 安装、冷启动，使用系统默认语言及切换应用语言，确认没有缺失系统类或原生符号错误。
2. 连续和长按方向键，浏览首页、搜索结果、详情及设置；确认无焦点丢失、输入积压。
3. 分别播放设备可硬解的 H.264 和 H.265 资源，检查字幕、音轨、暂停、快进快退及换源。
4. 连续播放 30 分钟并反复切集，记录 Java 堆、PSS、系统内存、卡顿和进程退出情况。
5. 逐项开启弹幕、视频预览、视觉效果、磁盘缓存及后台会话，重启应用确认持久化，并记录各项性能代价。
6. 核查本地 BT 与自动验证码识别不出现在可用功能中，人工验证码处理有可达入口。
7. 记录 APK 大小、安装后占用及缓存增长；剩余空间不足时验证错误提示和清理行为。

## 优化发布回归

- API 23 启动回归 CI 39772124256 已复现 `PublicDns.lookup` 使用系统缺失的 `CompletableFuture` 导致退出；当前实现使用 API 23 支持的 CountDownLatch，修复后的运行结果待 CI 验证。
- CI 39777057347 已复现 AGP 对 ndk.abiFilters 与非 universal ABI splits 的配置冲突；构建使用兼容配置，发布资产仍仅选择 ARM32 APK。
- 优化发布流程运行 ktor-client host tests、实际 AAR 审计、R8 Release 打包、资源裁剪、实际签名与清单检查、DEX 未压缩体积检查及 API 23 类型引用扫描。
- DEX 扫描读取类型表，不将日志文本中的类名当成系统类引用；阻止 CompletableFuture 平台类型残留，其他 Java API 类型列入报告。存在类型引用不等于路径可达，报告不能替代运行测试。
- MiTV4-ANSM0 实机打开播放页时，画中画控制器在构造阶段调用 API 24 的 `Activity.isInPictureInPictureMode` 导致 `NoSuchMethodError`。画中画判定在 API 26 以下直接返回不支持，构造阶段仅在支持画中画时读取小窗状态。依赖审计只检查 AAR 声明的 minSdk，DEX 扫描只检查 Java API 类型，均无法发现源码直接调用的高版本系统方法；修复后的播放页需在目标电视复测。
