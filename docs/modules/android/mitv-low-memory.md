# 小米电视低版本与低内存兼容

> 模块职责：为旧版 Android、1GB 内存电视提供可安装且可稳定播放的独立兼容构建。
> 负责人：GPT-6
> 系统模块：android
> 评审状态：用户已确认核心功能与可选开关；剔除不符合设备系统及硬件要求的功能。
> 关联模块：app/android、app-platform、ui-foundation、ui-tv、app-data、video-player、build-logic。

## 已确认的需求与事实

- 目标仓库为 https://github.com/CharlesHYF/izuko-tv，当前本地提交与该仓库 main 一致。
- 目标为 MiTV4-ANSM0，小米电视 4A 43 英寸，代号 xmen，Android 6.0.1 / API 23，固件 21.11.13.2897。
- 设备为纯 32 位系统，ABI 为 armeabi-v7a；交付包只包含此 ABI，所有原生依赖均须检查对应产物。
- 总内存约 1GB，常规 Java 堆上限 128MB，大堆上限 256MB；Java 堆上限不等于进程总内存预算，还须计入 native、图形及系统解码资源。
- Android 界面为 1280x720、213dpi，面板为 1920x1080；界面图片按实际显示尺寸解码，视频输出能力单独通过播放器验证。
- 存储剩余约 513MB，安装空间、应用数据与磁盘缓存须一起纳入验证，不默认开启视频磁盘缓存或离线下载。
- 设备报告 H.264 / H.265 硬解支持、不支持 4K；默认资源选择推荐最高 1080p，具体 profile、level、码率及音轨能力需实际解码验证。
- 网络为 2.4GHz Wi-Fi，有线网络可用但当前未连接；网络卡顿与内存回收须分别采集证据。
- 用户要求把操作流畅度作为首要验收条件，以其电视上 CleanYourTV 苹果风格桌面的跟手体验作为主观参照；不把静态桌面与联网视频应用视为相同负载。
- 开发及构建使用 Docker，不安装或更换宿主机 JDK、Android SDK，不修改宿主机全局环境配置。
- 开发环境须能够在另一台设备重建；缓存可以丢弃，不作为构建必需输入。
- 当前默认 minSdk 为 27，兼容构建 `ani.android.legacy=true` 的 minSdk 为 25。
- 当前 Room 为 2.8.4、Media3 为 1.9.0；这两个系列要求 API 23，与目标系统最低版本一致；其他依赖仍须审计。
- 图片缓存已经按物理内存设置，1GB 设备上限为 32MiB；兼容改造需要评估缓存之外的占用。
- 播放缓冲对限速源允许最多 120 秒前向缓冲；实际内存还受 Media3 分配策略、码率、解码器等约束，不能将时长直接当作内存占用。

## 隔离的 Docker 开发环境

### 功能描述

提供版本固定的容器构建定义和操作说明，容器内安装 JDK、Android SDK、构建工具及测试依赖。所有 Gradle 操作经过 `scripts/gradle-lock.sh`。

### 入参要求与参数

| 参数 | 要求 | 用途 |
| --- | --- | --- |
| 源代码 | 指定提交的项目源码 | 可复现构建输入 |
| 构建任务 | 明确 TV 构建变体 | 生成兼容包或运行测试 |
| ABI | 从电视读取 | 选择电视实际支持的原生库 |
| 构建配置 | 项目内维护，敏感值通过运行时注入 | 避免依赖本机路径及泄露凭据 |

### 返回与约束

- 返回 APK、测试报告、依赖兼容报告及可追踪的构建日志。
- Gradle 用户缓存、SDK 与项目构建目录使用本任务专属容器目录或卷，避免向宿主机已有构建目录写入 Linux 产物。
- 不挂载宿主机 JDK、Android SDK、用户主目录或 Docker socket；不使用特权模式。
- 仅使用明确指定的任务资源，不清理其他容器、镜像或卷，不执行全局 prune。
- 真机测试与 APK 构建分开；Linux 容器不默认具备 macOS 上的设备或模拟器访问能力。

## 系统版本兼容

### 功能描述

按设备实际 SDK 确定兼容构建的最低版本，对依赖、系统接口、文件访问、网络证书及原生库逐项验证。

### 入参要求与参数

| 参数 | 要求 | 用途 |
| --- | --- | --- |
| SDK | 已确认 23 | 审计高于 API 23 的系统调用 |
| ABI | 已确认 armeabi-v7a | 验证播放器、字幕、网络等原生库 |
| 故障现象 | 安装失败、启动退出、卡顿或播放退出 | 区分系统兼容、性能及媒体解码问题 |

### 返回与异常处理

- API 23：审计所有直接与传递依赖的最低 SDK，补齐 API 24 及以上调用的兼容实现或功能保护。
- 本模块只承诺经验证的 API 23 设备组合，API 22 不在本次适配范围。
- 不使用 `tools:overrideLibrary` 掩盖未经验证的运行时兼容问题。
- 检查老系统 TLS、证书链及 WebView 的实际能力；不通过关闭证书校验解决联网问题。
- ABI 或解码器不支持的媒体给出可理解的错误，并允许选择其他可用资源。
- 只有在对应系统及 ABI 上通过安装、启动和播放验证后，才标记该组合受支持。

## 低内存运行策略

### 功能描述

以单次播放所需的资源为中心限制内存，保留用户确认的功能。通过独立策略文件与少量接入点控制行为。

### 入参要求与参数

| 参数 | 要求 | 用途 |
| --- | --- | --- |
| 物理内存 | 系统报告值 | 识别 1GB 设备 |
| 应用堆上限 | ActivityManager 报告值 | 制定应用内预算 |
| 系统低内存标记 | 作为辅助信息 | 不假设所有 1GB 厂商系统都正确设置该标记 |
| 功能范围 | 用户确认后确定 | 决定默认禁用、按需启用及保留功能 |

### 返回与策略范围

- 策略覆盖图片解码尺寸与缓存、背景效果、预加载、播放器缓冲、WebView 会话数量、数据源查询并发及后台任务。
- 播放缓冲同时考虑字节预算与可起播门槛，避免内存上限与重缓冲门槛相互冲突。
- 退出播放和切换资源时验证播放器、预览及页面资源释放情况。
- 符合系统及硬件要求的高开销功能保留设置开关，默认关闭；不兼容的功能及依赖从目标构建中剔除。
- 不以 `largeHeap` 或频繁强制 GC 代替资源预算。
- 具体内存预算根据电视可用内存、进程 PSS、Java/native/图形占用和长播测试确定，当前不承诺未经实测的峰值。

### 默认功能配置

| 功能 | 建议行为 | 原因 |
| --- | --- | --- |
| 搜索、详情、选集、在线播放、观看记录 | 保留 | 核心观看流程 |
| Bangumi 登录与收藏、手机控制台 | 保留，按使用场景加载 | 复用已有账号与输入能力 |
| 视频轨道选择 | 推荐不高于 1080p，优先设备可硬解的轨道 | 避免选择 4K 或落入高开销软件解码 |
| 海报、背景 | 保留静态图片，按 720p 界面实际尺寸解码 | 限制解码内存与图形开销 |
| 复杂动画、背景模糊、视频缩略图预览 | 默认关闭 | 减少图形和额外取帧开销 |
| 本地 BT | 不包含 | 当前 Anitorrent 原生依赖要求 API 26 |
| 离线下载、视频磁盘缓存、跨页面保留播放会话 | 默认关闭，兼容部分保留设置开关 | 避免挤占内存及剩余存储 |
| 弹幕 | 默认关闭，可手动启用并限制密度 | 保留用户选择，控制默认占用 |
| 数据源查询与 WebView | 限制并发并按需释放 | 控制搜索和解析时的峰值 |

## 验证与交付

- 容器中运行相关单元测试、交互测试、依赖及系统 API 兼容检查，并构建启用 R8 的 release 测试包。
- 对实际最低 SDK 验证冷启动、搜索、详情、选集、播放、跳转、换源、退出重进与观看记录恢复。
- 在 1GB 真机上采集启动、浏览、播放、反复切集与持续播放的内存；模拟器通过不能替代真机解码和内存验证。
- 建议验收场景为连续播放 30 分钟、反复切集及退出重进，记录 OOM、系统终止、Java 堆与进程 PSS；记录最终 APK 大小、安装后占用和缓存增长。
- 验证低内存策略不产生无限等待缓冲、反复重试或页面焦点异常。
- 交付前确定并执行与本次兼容范围匹配的回归测试；未执行的检查明确说明。
- 交付可迁移的 Docker 配置、构建说明、测试结果及适配实际 ABI 的 APK。

## 交互流畅度

### 功能描述

在 720p 界面下保证遥控器连续导航、滚动、进出详情及播放控制的响应优先级，视觉效果服从输入响应。加载网络数据时先显示可操作界面和明确的加载状态。

### 入参要求与参数

| 参数 | 要求 | 用途 |
| --- | --- | --- |
| 目标设备 | MiTV4-ANSM0，API 23，armeabi-v7a，1GB 内存 | 性能验收必须使用此设备 |
| 输入场景 | 连按、长按方向键、确认与返回 | 验证跟手、焦点与输入积压 |
| 显示刷新周期 | 实测获取 | 计算帧时间预算，不假设设备固定 60Hz |
| 测试构建 | release 优化包，明确首次运行与预热状态 | 避免用 debug 结果代表发布性能 |

### 行为与实现边界

- 复用项目已有的原生 View 海报墙、背景与列表实现，先测量焦点、布局、图片解码和动画的开销，再决定局部调整。
- 不把全量 UI 重写作为既定方案；确需增加轻量原生页面时，在独立 TV 文件中实现并复用共享业务状态。
- 焦点反馈优先使用低开销的描边、颜色或短时变换，避免整屏每帧重绘及多层同时动画。
- 网络、解析、数据库及图片解码不阻塞输入处理；连续输入时合并无效的预加载工作，避免任务排队放大延迟。
- 首页、详情和播放器切换时只保留必要资源；播放期间单独验证唤出控制层和切集的响应。

### 返回与验收

- 输出各场景的输入响应、帧时间分布、卡顿记录和内存数据，并在同一设备、相同操作下比较改造前后表现。
- 性能目标为热态焦点可见反馈 P95 不超过 100ms、连续导航帧时间 P95 不超过两个实测刷新周期；这些是待真机验证的目标，不能在无数据时声称达成。
- 统计帧时间时区分按键反馈、滚动和转场，静止帧不参与稀释结果；连续导航期间不得出现明显的按键积压、焦点丢失或长时间界面冻结。
- 网络搜索与起播时间单独统计，不用界面帧率掩盖网络等待，也不用网络慢解释本地输入迟滞。
- 用户在目标电视上确认跟手体验，作为量化数据之外的验收条件。

## 依赖兼容性实查

在独立 Docker 容器中从 Maven Central 和 Google Maven 下载下列正式 AAR，读取 `AndroidManifest.xml` 的 `uses-sdk`，检查 `jni/armeabi-v7a`；对 BT 与部分播放器原生库读取 ELF `.note.android.ident`。此检查不等同于整包依赖闭包检查或真机运行验证。

| 依赖或能力 | 实查结果 | 目标版本处理 |
| --- | --- | --- |
| Anitorrent native Android 0.2.0 | 清单最低 API 26，ARM32 ELF 编译目标 API 26 | 剔除本地 BT 及其原生运行库，不提供开启开关 |
| ONNX Runtime Android 1.22.0 | 清单最低 API 24，含 ARM32 库 | 剔除离线自动识别验证码及其运行库；保留可用的人工处理流程 |
| Media3 ExoPlayer / Transformer 1.9.0 | 清单最低 API 23 | 保留，视频预览仍须单独验证实际驱动兼容性与开销 |
| Room runtime Android 2.8.4 | 清单最低 API 23 | 保留 |
| Compose UI Android 1.12.1 | 清单最低 API 23 | 保留共享界面与状态基础 |
| JetBrains Adaptive 1.3.0-rc01 的 Android 实现 | adaptive、adaptive-layout、adaptive-navigation 清单最低 API 24 | 兼容构建固定这三个模块到 1.2.0；其 Android 变体使用最低 API 23 的 AndroidX 实现，默认构建保持原版本 |
| Navigation 2.10 的 Android 实现 | JetBrains 2.10.0-beta01 与 AndroidX 2.10.0 的 common/runtime/compose 清单最低 API 24 | 兼容构建使用 JetBrains 2.9.2 及其对应 AndroidX 2.9.7；AndroidX 2.9.7 清单最低 API 23 |
| Lifecycle runtime Android 2.11.0 | 清单最低 API 23 | 保留 |
| SQLite bundled Android 2.6.1 | 清单最低 API 23，含 ARM32 库 | 保留 |
| DataStore Android 1.2.0 | 清单最低 API 23 | 保留 |
| Mediamp ExoPlayer Android 0.5.1 | 清单最低 API 21，含 ARM32 音频处理库 | 保留 |
| Mediamp FFmpeg Android 0.5.1 | 清单最低 API 21，含 ARM32 库 | 按实际使用保留；不以软件视频解码作为默认路径 |
| ass-kt / ass-media 0.5.0-beta01 | 清单最低 API 21，ass-kt 含 ARM32 库，所查 ELF 编译目标 API 21 | 保留字幕 |
| Conscrypt Android 2.7.0 | 清单最低 API 21，含 ARM32 库 | 保留，旧系统实际 TLS 连接待验证 |
| 仓库自带 libani_dataspace.so / libffmpegJNI.so | ARM32 ELF 编译目标 API 21 | 静态检查通过，最终 APK 继续检查动态库依赖 |
| Android 主屏预览频道 | 入口代码要求 API 26 | 目标设备不提供此能力 |

制品定位：Maven Central 路径分别为 `org/openani/anitorrent/anitorrent-native-android/0.2.0`、`com/microsoft/onnxruntime/onnxruntime-android/1.22.0`、`org/conscrypt/conscrypt-android/2.7.0`、`io/github/peerless2012/ass-kt/0.5.0-beta01`；版本与项目版本目录一致。

## 真机验证信息

1. 当前失败现象是否仅为系统版本导致无法安装，还是已有可安装版本存在卡顿或退出。
2. 首次真机验证前确认用户设备访问方式，项目内其他共享测试设备不能替代此电视。
